# RAG 图关系检索引擎架构

## 概述

生产级本地 RAG 检索引擎，支持**图关系检索**（基于 Markdown `[[双链]]` 的知识图谱）+ 混合检索（关键词 + TF-IDF向量），持久化热加载，完全离线运行。

> **核心理念**：知识库中的 `[[双链]]` 标记天然形成节点关系图，检索时不仅匹配关键词，还沿图的边追踪关联节点，大幅提升召回率和准确性。

## 技术栈

- **检索引擎**：ChromaDB（向量存储） + 自实现 TF-IDF + 倒排索引
- **API 层**：FastAPI + WebSocket（预留）
- **分词**：零依赖中文滑窗分词（双字+单字）
- **持久化**：JSON 文件缓存（inverted_index.json + chunks_meta.json）

## 核心架构：图关系检索 + 混合召回

### 知识库即知识图谱

Markdown 中的 `[[双链]]` 标记天然形成节点关系图：

```
                    ┌─────────────────┐
                    │  operating-doctrine │
                    │  (链接数=10)      │
                    └────────┬────────┘
              ┌──────────────┼──────────────┐
              │              │              │
    [[双链]]↓         [[双链]]↓      [[双链]]↓
   ┌─────────┐     ┌─────────┐     ┌─────────┐
   │ user-   │     │ assistant-│     │ work-   │
   │ profile │     │ ecosystem │     │ style-  │
   │ (4条)   │     │ (4条)     │     │ feedback│
   └─────────┘     └─────────┘     └─────────┘
```

**检索时不仅匹配关键词，还沿图的边追踪关联节点：**

```python
def graph_aware_search(query, top_k=5):
    # Step 1: 关键词倒排索引召回
    keyword_hits = inverted_index.search(query)  # 35%

    # Step 2: 图扩展 — 命中文档的 [[双链]] 邻居也加入候选
    expanded = set()
    for hit in keyword_hits[:3]:
        links = extract_wikilinks(hit.path)  # 提取 [[xx]] 链接
        expanded.update(links)              # 邻居节点加入候选集

    # Step 3: 对扩展节点做 TF-IDF 向量召回 (15%)
    # Step 4: 融合排序（原始命中 > 图扩展）
    return merge_and_rank(keyword_hits, expanded)
```

### 三路混合检索

| 通路 | 算法 | 权重 | 作用 |
|:-----|:-----|:----:|:-----|
| **关键词召回** | 倒排索引 + BM25变体 | 35% | 精确术语匹配 |
| **图关系召回** | `[[双链]]` 邻居扩展 | 15% | 关联知识推荐 |
| **TF-IDF向量** | cosine相似度 | 50% | 语义理解 |

### 图扩展效果示例

搜索 "操作守则" 时：

```

  ✅ assistant-ecosystem.md  ← operating-doctrine 链接到它

  ✅ work-style-feedback.md  ← operating-doctrine 链接到它

```

## 核心设计决策

### 1. 为什么用 TF-IDF 而不是 Embedding 模型？

- 无网络依赖：HuggingFace 被墙，无法下载 sentence-transformers
- 速度优势：TF-IDF 计算 <1ms，Embedding 推理 ~50ms+
- 效果足够：对于中文专业术语（MCP、飞书、Jarvis）关键词匹配更精确
- 可解释性强：可以清晰说出"因为'协议'这个词匹配了8个块"

### 2. 为什么引入图关系检索？

纯关键词检索的问题：搜"客服"只匹配含"客服"的文件，但 `[[知识图谱]]` 关联的"多轮对话""意图识别"相关内容被漏掉。

图关系检索解决：沿 `[[双链]]` 边追踪，把关联知识也纳入候选，召回率提升显著。

### 3. 持久化方案

| 文件 | 大小 | 内容 |
|:-----|:----:|:-----|
| chroma.sqlite3 | ~2MB | 向量数据（ChromaDB内部） |
| inverted_index.json | ~400KB | 关键词→chunk ID映射 |
| chunks_meta.json | ~240KB | chunk标题/路径/预览 |

重启加载时间：<100ms（纯JSON读取）

### 4. 分词策略

```python
def tokenize(text):
    # 英文单词
    words = re.findall(r'[a-zA-Z0-9_]+', text.lower())
    # 中文单字
    cn_chars = re.findall(r'[一-鿿]', text)
    for i in range(len(cn_chars)):
        words.append(cn_chars[i])
        if i+1 < len(cn_chars):
            words.append(cn_chars[i] + cn_chars[i+1])  # 双字滑窗
    return list(dict.fromkeys(words))  # 去重保序
```

示例："MCP协议是什么" → ["mcp", "协", "协议", "议", "是", "什么"]

## 已知限制

1. 分词为简单滑窗，不支持语义理解（如"AI助手"不自动联想到"Jarvis"）
2. 图扩展仅1跳（直接邻居），未实现随机游走等高级算法
3. 不支持增量更新（需全量重建）
4. 无权限控制（本地服务，暂无需求）
