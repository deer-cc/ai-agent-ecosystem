# 系统架构总览

## 设计理念

> 不是"调 API 写脚本"，而是构建一套**可进化、可编排、可治理**的 AI 应用系统。

## 核心设计决策

### 1. 叶子↔小天协议分离

传统方案：Claude Code 既是大脑又是手脚。
本方案：**叶子只规划，小天只执行**，通过 JSON 指令通信。

- 叶子输出：`{"task_id": "001", "action": "read_file", "params": {...}}`
- 小天回执：`{"status": "OK", "result": {...}, "execution_time_ms": 5}`
- 错误现场原样返回，不带建议，不带 fallback

### 2. MCP 五层能力运用

不只是 Tools 调用，完整运用 MCP 协议的五层能力：

| 层 | 能力 | 本项目使用 |
|:---|:-----|:----------|
| Tools | 工具调用 | Playwright, DevTools, 自定义MCP |
| Resources | 资源读取 | 飞书文档 URI, 知识库文件 |
| Prompts | 提示模板 | 领域特定 prompt 复用 |
| Sampling | 服务端LLM | 待扩展 |
| Roots | 根目录 | Claude Code 自动注入工作目录 |

### 3. 守护进程高可用

guardian 守护进程解决"服务挂了没人知道"的问题：

- 每 60 秒巡检所有服务
- 连续 3 次失败触发自动重启
- 告警通过 dispatcher 推送到飞书
- 指数退避重试 + 去重节流

## 技术栈清单

| 层级 | 技术 | 用途 |
|:-----|:-----|:-----|
| LLM | Claude (Anthropic) / DeepSeek | 主模型路由 |
| 桥接 | cc-connect (Go) | 跨平台消息路由 |
| Agent框架 | Claude Code + Skills | 多Agent编排 |
| MCP | @modelcontextprotocol/sdk | 工具协议层 |
| 桌面控制 | Python pyautogui + pywin32 | 屏幕/鼠标/键盘 |
| 浏览器 | Playwright MCP | Web自动化 |
| 知识库 | Obsidian + 倒排索引 | RAG检索 |
| 守护 | Python guardian | 服务高可用 |
| 推送 | Node.js dispatcher | 飞书告警通道 |

## 性能指标

| 指标 | 数值 | 说明 |
|:-----|:-----|:-----|
| 消息路由延迟 | <200ms | cc-connect WebSocket → Claude Code |
| 桌面操作延迟 | ~50ms | Python 原生 vs 旧版 500ms (10x提升) |
| 守护巡检周期 | 60s | 可配置 |
| 知识检索速度 | <100ms | 倒排索引 |
| 告警去重窗口 | 5min | 同内容只发一次 |
