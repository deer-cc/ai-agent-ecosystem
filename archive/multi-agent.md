# 多 Agent 编排系统设计

## 问题定义

单个 LLM 模型在处理复杂任务时有局限性：
- 上下文窗口有限，长对话质量下降
- 工具调用边界模糊，容易"贪多"
- 缺乏领域专业化，什么都会一点但都不精

## 解决方案：叶子 + 领域专家架构

```
                    ┌─────────────┐
                    │   用户      │
                    └──────┬──────┘
                           │ 碎片想法 / 明确指令
                    ┌──────▼──────┐
                    │    叶子     │  ← 战略预判 + 意图翻译
                    │  (规划层)   │     不给唯一答案，给多选项
                    └──────┬──────┘
                           │ 确认后的明确方案
           ┌───────┬───────┼───────┬───────┐
           ▼       ▼       ▼       ▼       ▼
        ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐
        │ 小鱼 │ │ 阿秋 │ │ 小白 │ │松鼠│ │小天  │
        │创作  │ │图片  │ │投资  │ │视频│ │执行  │
        └──────┘ └──────┘ └──────┘ └──────┘ └──────┘
```

## 叶子 (规划层) 职责

叶子不做两件事：
1. **不替用户做决定** — 给 2-3 条路径，让用户选
2. **不理解意图前不执行** — 先确认，再行动

叶子只做一件事：把模糊的需求翻译成明确的方案。

### 十大能力

1. **想法收集池** — idea-inbox.md，翻译+追问
2. **意图预测** — 多路径预测真实需求
3. **架构规划** — A/B/C 三条实施路径对比
4. **可行性评估** — 三维评估（技术/时间/资源）
5. **方向守护** — 发现范围漂移/优先级颠倒时提醒
6. **项目状态追踪** — project-tracker.json 全生命周期
7. **想法关联发现** — 发现隐藏联系，给出合并建议
8. **执行后复盘** — 返回问"结果匹配吗"
9. **沟通风格自适应** — 感知模式调整输出密度
10. **时间维度规划** — 优先级矩阵 + 时间估算

### 工作流程（9步）

```
Step 0: 入场检查 — 读快照 + 上下文注入
Step 1: 接收想法 → 存 inbox + 检查关联
Step 2: 分析上下文 + 感知沟通模式 → 预测意图
Step 3: 给出 2-3 条路径（不等确认）
Step 4: 等用户选择/补充
Step 5: 出详细方案（含多路径对比）
Step 6: 等确认 → 路由执行
Step 7: 执行中守护方向 → 发现偏差温和提醒
Step 8: 完成后复盘 → 更新 tracker + 生成快照
Step 9: 定期检查关联 + 优先级重排
```

## 领域专家 (Skill 层) 设计

每个 Skill 是一个独立的 Markdown 指令集 + 可选的 Python/Node 脚本：

| Skill | 领域 | 输入 | 输出 |
|:------|:-----|:-----|:-----|
| 小鱼 | 内容创作 | 主题/大纲 | PPT(.pptx)/文案/SVG图表/漫画 |
| 阿秋 | 图片生成 | 描述词 | AI生图/PSD分层/带水印成品 |
| 阿甘 | 资料管理 | 文件/指令 | 整理好的虚拟资料包 |
| 小白 | 投资分析 | 股票代码 | 持仓研判报告+SVG图表 |
| 松鼠 | 视频制作 | 文案/素材 | 配音+合成视频 |
| Deer | 运营策略 | 平台/数据 | 选题/脚本/数据报告 |
| 小月 | 闲鱼运营 | 商品/文案 | 标题/详情/引流策略 |
| 控制小助手 | 桌面控制 | 操作指令 | 截图/点击/键盘/窗口管理 |

## 叶子↔小天 通信协议

### 指令格式

```json
{
  "task_id": "string (required)",
  "action": "string (required)",
  "params": {},
  "expected": "string (optional)",
  "priority": "high|normal|low",
  "timeout": 5000
}
```

### 支持的 Action（15个）

| Action | 类型 | 说明 |
|:-------|:----:|:-----|
| `read_file` | 🟢 | 读取文件 |
| `write_file` | 🟡 | 写入文件 |
| `append_file` | 🟡 | 追加文件 |
| `delete_file` | 🔴 | 删除文件 |
| `list_dir` | 🟢 | 列出目录 |
| `exec_command` | 🟡 | 执行命令 |
| `http_get` | 🟡 | HTTP GET |
| `http_post` | 🟡 | HTTP POST |
| `get_process` | 🟢 | 查进程 |
| `kill_process` | 🔴 | 杀进程 |
| `restart_service` | 🔴 | 重启服务 |
| `start_service` | 🟡 | 启动服务 |
| `stop_service` | 🟡 | 停止服务 |
| `read_memory` | 🟢 | 读记忆 |
| `write_memory` | 🟡 | 写记忆 |

### 错误码（11个）

`JSON_PARSE_ERROR` · `ACTION_NOT_FOUND` · `MISSING_PARAM` · `PERMISSION_DENIED` ·
`FILE_NOT_FOUND` · `DIR_NOT_FOUND` · `EXEC_TIMEOUT` · `EXEC_ERROR` ·
`NET_ERROR` · `GUARD_INTERRUPT` · `PATH_PROTECTED`

## 安全边界

| 级别 | 操作 | 示例 |
|:----:|:-----|:-----|
| 🟢 自动 | 截图、查看窗口、读取文件 | 无需确认 |
| 🟡 预告 | 点击、输入、写文件、HTTP请求 | 执行前说一声 |
| 🔴 确认 | 删除文件、发送消息、杀进程 | 必须用户明确同意 |

## 与传统的区别

| 维度 | 传统方案 | 本方案 |
|:-----|:---------|:-------|
| Agent通信 | 开发者手写 if/else 分发 | JSON 指令协议，可扩展 |
| 错误处理 | 各自 catch | 统一 error_code 体系 |
| 安全防护 | 无 | 三级安全边界 + 路径保护 |
| 监护机制 | 无 | 独立监护系统 + SIGTERM 强杀 |
| 可观测性 | 无 | task_id 全链路追踪 |
