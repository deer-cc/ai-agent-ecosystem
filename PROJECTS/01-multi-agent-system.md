# 项目一：多 Agent LLM 编排系统

## 一句话定位

> 一套完整的 Multi-Agent 系统：叶子（战略预判）规划 → 领域专家执行 → 监护系统保障

## 技术栈

Python · JSON协议 · Claude Code Skills · Obsidian知识库 · GitHub Actions

## 核心设计

### 问题分析

传统单 Agent 的局限性：
- 上下文窗口有限，长对话质量衰减
- 工具调用边界模糊，容易"贪多"
- 缺乏领域专业化

### 解决方案

```
用户 → 叶子(分析/规划) → 确认方案 → 路由到领域专家 → 执行反馈 → 复盘进化
              ↑                                      ↓
         idea-inbox          ←───── project-tracker ←── 决策日志
```

### 关键模块

| 模块 | 文件 | 职责 |
|:-----|:-----|:-----|
| 叶子大脑 | `叶子\leaf_brain.py` | 主入口，协调所有能力 |
| 用户画像 | `叶子\data\user_model.json` | 记忆偏好 + 决策历史 |
| 项目追踪 | `叶子\project-tracker.json` | 全生命周期状态管理 |
| 想法池 | `叶子\idea-inbox.md` | 持久化想法收集 |
| 通信协议 | `PROTOCOLS\leaf-tian-protocol-v1.md` | 叶子→小天指令规范 |
| 守护进程 | `叶子\leaf_daemon.py` | 后台常驻 + API服务 |

## 核心能力

### 1. 意图预测（非猜答案，给路径）

```
你：我想做个自动抓取热榜的机器人
叶子：我猜你想要的是以下方向之一——

A. 「素材库」—— 持续积累内容，供后续使用
B. 「趋势追踪」—— 发现热点第一时间通知
C. 「自动化运营」—— 发现热点自动生成并发布

选哪个？还是三个都要？
```

### 2. 方向守护（温和纠偏）

```
⚠️ 等一下，我想提醒你——

① 范围漂移：你之前说想要 MVP，但现在加了 [新功能]。
   这是解决 [同一个问题] 还是 [衍生问题]？
   如果是衍生问题，建议先让 MVP 跑起来。

② 优先级：你现在在做 [次要功能]，但 [核心功能] 还没跑通。
```

### 3. 执行后复盘（进化机制）

```
📋 复盘：[项目名称]

结果和你最初想要的匹配吗？
□ 方向对了吗？ □ 有漏掉的吗？ □ 下次怎么改进？

叶子改进：[下次遇到类似需求时，我会改变的做法]
```

## 成果数据

- **已实现的Action**：15 个（读/写/删/命令/网络/进程/MCP）
- **错误码体系**：11 个（全覆盖错误场景）
- **项目追踪**：7 个项目全生命周期管理
- **决策记录**：8 条历史决策，持续学习用户偏好
- **风格适配**：5 种用户模式自动识别

## 与简历的结合

**项目描述（企业语言）：**
> 设计并实现了一套基于 LLM 的多 Agent 编排系统，采用"规划层+执行层"分离架构，
> 通过 JSON 指令协议实现叶子（战略预判）与执行器的解耦通信。
> 系统支持 15 类原子操作、11 类错误码、三级安全边界，
> 具备意图预测、方向守护、执行复盘等核心能力。

**面试亮点：**
- MCP 协议五层能力的完整理解与实践
- 多 Agent 之间的通信协议设计
- 安全边界与监护系统的工程设计
- 用户画像学习 + 自适应沟通
